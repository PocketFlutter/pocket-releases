# Pocket visual novel engine research and acceptance baseline

> Research date: 2026-11-07. The official documentation and release repositories linked here establish licensing, compatibility, and capabilities for the versions reviewed. Before integrating third-party code, check the corresponding version's `LICENSE`, dependencies, and asset terms. This document provides product research and excludes legal advice and prices, which can change independently of architecture.
>
> This is a living product and acceptance baseline. When completing a capability, record its implementation entry, runtime evidence, and untested areas in the applicable row. Acceptance requires real Guest/Host behavior.

## Product direction

Build a reusable visual novel runtime and an editable Showcase mini-game demonstrating the full feature set in Pocket. The scope includes writing, narrative state, staging, audio, save/load, reading tools, UI, localization, debugging, accessibility, extensions, and packaging. Implementation phases determine dependency order while preserving the full scope.

**The game, editor, and debug preview share one `StoryDefinition` stored as `story.json`, and one JS runtime.** The graph editor edits the same document through structured events. Characters, variables, assets, choices, conditions, and commands have explicit types and stable IDs. Preview calls the same JS core and builds from the same story and assets. Keep one graph, narrative state machine, and runtime. Add controlled breakpoint, variable inspection, and navigation APIs to the core before exposing those operations. User scripts never execute through `eval`.

Ink/Inky/InkJS are candidates for middleware interoperability. Ink is an MIT-licensed interactive narrative language whose compiler emits JSON and whose runtimes include JavaScript. Compatibility with Pocket's pinned PocketJS/QuickJS compiler and guest features still needs verification. Use Ink as a reference for capabilities and language design. A future import/export path or verified adapter should use one runtime with a single owner of story state. [Ink overview](https://www.inklestudios.com/ink/), [official repository and runtime](https://github.com/inkle/ink)

The Pocket host provides rendering, input/IME, lifecycle, resource decoding, and explicitly registered native capability transport. JS owns story state, the editor, UI composition, auto/skip policy, and records. Dart plugins supply the IO and playback boundaries that JS cannot provide directly. At the time of this review, `demo/pubspec.yaml` declared `video_player`, and repository inspection found no BGM, SFX, or voice API for Pocket VN. Real audio output is a required host capability.

## Pocket implementation priorities and editor design

The following implementation order preserves every target feature. Research supports readable stories, stable identifiers, typed commands, runtime preview, variable debugging, and portable data boundaries. Pocket keeps its own runtime and editor.

1. **Data model and JS story runtime.** A single `StoryDefinition`/`story.json`, stable node/line/choice IDs, and validated typed text, choice, condition, set-variable, jump/call, wait, stage, audio, and gallery/glossary events. The runtime saves story position, call stack, variables, and visited markers. Expressions and commands use a controlled registry without evaluating arbitrary project text through `eval`.
2. **Editable Story Editor and debug preview.** Create, open, and save story.json. Edit typed characters, variables, assets, labels, choices, and conditions. Add, delete, move, and reorder links and nodes in the graph or timeline and save the same file. Diagnose references, duplicate IDs, unreachable nodes, loops, dead ends, and missing assets or translations. Play, pause, step, continue, reset, break, inspect variables and the story pointer, and jump to a node. Editor and playtest state must be independently verifiable. The acceptance path is edit → buildGuest → native execution.
3. **Complete main-story staging.** Titles/chapters, backgrounds/scenes, portraits with expression/position/layer, typewriter text and rich-text markup, time limits/wait/input, and optional branches and endings. Scripted fades, slide and zoom, shake, and character entry/exit. CG and scene replay gallery with multiple ending unlocks.
4. **Audio and reading experience.** A thin native plugin supplies playback. JS manages BGM/SFX/voice cues, group volumes, interruption and transition policy, and dialogue sync. Support BGM looping/fades, optional voice keyed by line ID, auto waiting for voice, mute, and volume settings. Verify observable playback output in addition to host requests.
5. **Player tools and persistence.** Title, preferences, save/load, pause, log/backlog, quick saves and autosaves, and multiple manual slots with time, chapter, latest dialogue, and optional thumbnail. Load restores characters, scene, music, route variables, and rollback history. Bounded rewind/rollback restores equivalent state along with text position. Language, volume, display, and accessibility preferences persist independently from global progress and ending/CG unlocks.
6. **Read tracking, autoplay, and skip.** Every line has a stable ID. Mark it read only on full display or tap to complete, and retain this across saves. Skip defaults to seen-only and stops at unread text on branches. All-skip requires a separate explicit setting with a clear explanation. Configurable auto delay respects user input, voice completion, and choices. Make skip policy for cutscenes and voice configurable.
7. **Localization, adaptation, and accessibility.** Import and export story and UI resources separately in CSV, with stable IDs, diff checks, missing/extra translation reports, runtime locale switching, and fallback. Provide localized character names, UI, fonts, images, and voice assets. Reflow lengthy text, support dynamic font size, portrait/landscape and safe areas, and narrow-screen input and focus. Provide full keyboard, touch, and gamepad operation with visible focus and accessible semantics, plus text size, contrast, speed, reduced motion/flashing, pause, and voice subtitle options.
8. **Extensions and distribution.** Expose versioned, typed JS command, asset provider, and renderer adapter interfaces that preserve the story core. Supply resource manifests, validation, reproducible packaging, and actionable missing-resource errors. Use the pinned Guest compiler/engine and resource pipeline. Export the Demo project and execute it on the target Pocket host. Claim support only for targets that run in Pocket.

### Preferred visual editor patterns

- **Graph or timeline, property editor, and traceability to source.** Dialogic exposes a single timeline through visual and text views. Yarn Editor supplies node graph, preview, syntax diagnostics, project forms, and command definitions. TyranoStudio shows live tags and variables and offers asset management and coordinate preview. Pocket needs a graph with movable, connectable events, a typed inspector for selections and character/variable/asset editors, live preview, and an error panel. Every edit writes back to `story.json`. [Dialogic timeline and two editor views](https://docs.dialogic.pro/), [Yarn Editor](https://yarnspinner.dev/editor/), [TyranoStudio tools](https://tyranoscript.com/studio/)
- **Use author-facing terms.** Label story events with dialogue, choices, conditions, variables, character entry/exit, background, audio cue, and wait. Put low-level rendering/Host methods behind the command panel and extension registry. Preserve unknown and future events as editable raw JSON.
- **Use the same runtime in debug and release.** Run the current saved project in the actual engine. Error messages should link back to nodes or assets and variable views and the execution pointer should update live. The same `story.json` must build from Editor preview to buildGuest and the native Demo. Debug APIs expose only controlled pause, continue, step, breakpoints, read-only variable inspection, and safe-node navigation.
- **Support a complete authoring workflow.** Authors can add, edit, delete, duplicate, and reorder nodes, branches, conditions, variable values, characters and expression assets, audio/background references, language files, and sample save content. Save or export/import, then reopen and replay consistently. Unsupported runtime features show specific unavailable/error states in the editor.

## Scope boundaries

- The host stays thin. Keep one UI and layout engine and JS story state service. Keep Showcase logic out of the public SDK and use only the permitted retained sources outside old `pocket_host/`.
- Naninovel, VN Maker, and TyranoBuilder restricted source and bundled assets are out of scope. TyranoScript's terms at review prohibited runtime redistribution. Ren'Py and Kirikiri dependency bundles require a separate license inventory. Verify terms before using any Yarn YSPL adapter in a competing engine.
- Free tools, permission to sell their outputs, OSI licensing, and permission to redistribute or adapt the runtime are separate rights. References apply to the listed products and versions and provide background for legal review.
- A general 2D/3D game engine, IDE platform, cloud translation and collaboration, asset marketplace, and complete Live2D SDK are outside the first version. Live2D and advanced 2D puppets require an isolated extension interface and separate license and host feasibility reviews. The base Showcase needs actual portraits, expressions, layers, and animation.
- Version one story definition and asset manifest. An Ink importer/exporter is optional future interoperability work. The current story runtime uses the canonical definition.

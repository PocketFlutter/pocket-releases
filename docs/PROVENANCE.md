# Provenance and versions

- PocketJS upstream is `pocket-nexus/pocketjs`, pinned at revision `99924de47c62fa36f526a8791055d91cbbdb3836`.
- The source archive SHA-256 is `82d5d72ca242b5827379e0e7a53114bc9ee2093af0a9306336a5def543708cba`. `scripts/prepare_upstream.py` verifies it and extracts it into `.cache/pocketjs` under the SDK root.
- The Native and Flutter adapters were extracted from `native` and `packages/pocket_flutter` in the user's `PocketJSKit` and trimmed to the minimal host boundary. Upstream patches are retained in `native/patches`.
- The original demo provides reference components, interactions, system input, and app scenarios. The integration selectively migrates reusable pure JS logic and native bindings. The old Dart business tree, mock runtime, and AOT/OTA flows were left behind. See the [framework comparison](FRAMEWORK_GUIDE.md), [input reuse](INPUT_REUSE.md), and [scroll reuse](SCROLL_REUSE.md) for sources and gaps.
- `pocket_services` was adapted from PocketJSKit's signed-package, update, host, plugin, and stream modules. Dependencies on game configuration and business containers were removed. The signed guest manifest defines its own capability contract.
- JS composes `guest/ui` and the demo pages. `guest/ui/mobile.tsx`, `guest/mobile-pages.tsx`, and `guest/legacy.ts` adapt mobile composition, transitions, and glass for this repository. They reuse the old UIKit and Router's pure JS vocabulary and calculations. The old Dart hydration and second renderer are outside this integration.
- `package_info_plus` 8.3.0 demonstrates a real external Flutter plugin. The reusable `pocket_hardware` package compiles the `flutter.hardware` provider (Dart adapter, iOS and Android MethodChannel, and Texture manager) into the host through the standard Flutter plugin registry. Use `demo/integration_test/hardware_native_test.dart` to validate real permissions and Texture behavior on the target devices.
- `native/src/bytecode.rs`, the `pocketjs_bytecode` CLI, and `guest-rquickjs-bytecode.patch` were added here. They reuse the rquickjs 0.12.2 and QuickJS serialization APIs pinned in Cargo.lock.
- `pocket.registerSurface` in `native/src/lib.rs`, `PocketHostSurfaceOp` in `packages/pocket_flutter/lib/src/pocket_model.dart`, and the surface stack in `pocket_view.dart` and `pocket_surface.dart` implement this repository's `SURFACE_QUAD` bridge. Only the `glass` and `platformTexture` providers are allowed. The `liquid_glass.frag` shader used by `pocket_surface.dart` provides refraction on supported paths, with an explicit frosted fallback elsewhere.
- `editor/server.ts`, `editor/client/`, and `editor/test/editor_live_probe.ts` reuse the former PocketJSKit Editor's local project, build, and publish workflow. See [Editor reuse](EDITOR_REUSE.md) for source details. The adapted workflow uses the current guest scaffold, QJBC and PAK outputs, and `scripts/package_update.ts`. Multi-file GET and PUT enforce path, symlink, build output, key, and binary protection. `app.js` serves diagnostic use only.
- The audit cleanup removed the former `migrations` archive. The retained parent `pocketjs_flutter_demo` (excluding `pocket_host`) is the available reference. Current builds and execution have no dependency on that external source.
- Pocket is distributed under the [MIT License](../LICENSE). The original upstream MIT text remains verbatim at [`LICENSES/PocketJS-MIT.txt`](../LICENSES/PocketJS-MIT.txt) as the independent notice for pinned PocketJS and MicroTS. See [`LICENSING.md`](https://github.com/PocketFlutter/Pocket/blob/235b5b5589faf492f4a9fc3b7c0827bcd1d9de2c/LICENSING.md) for third-party terms. Caches, compiled artifacts, signing private keys, and user projects are outside the source delivery.
- The current toolchain baseline is Flutter 3.50.0, Dart 3.14.0, and Rust 1.93.1. The minimum compatibility baseline is Flutter 3.35.x and Dart 3.9.x. Bun installs compiler dependencies using the upstream lockfile.

## Implementation and validation scope

- `tests/mobile_ui.test.ts` covers mobile controls, four transition descriptors, the glass recipe, the surface registration text contract, and the route stack. `packages/pocket_flutter/test/pocket_surface_test.dart` covers surface descriptors, clip and paint order, and Texture admission and revocation. These tests establish source contracts and widget lifecycle boundaries. Visual agreement between Impeller and other renderers on physical devices remains outside their scope.
- `demo/test/hardware_plugin_test.dart` imports `pocket_hardware` directly and covers the descriptor, the Android-shaped contract, unsupported operations and timeouts, camera Texture cleanup, weather coordinates, and late results. `hardware_native_test.dart` uses the production MethodChannel registered by the standard plugin flow. Physical hardware verification requires the corresponding Android and iOS devices.
- `editor/test/editor_server.test.ts` covers Editor HTTP, state, and signing. `editor/test/editor_live_probe.ts` uses the real guest and compiler to verify QJBC, PAK, signed manifests and blobs, and `host.json`, and checks that bad source cannot publish an old build. Temporary workspaces and artifacts stay out of `host/assets/`.
- `packages/pocket_services/lib/src/pocket_plugin.dart` now handles activation failure and revocation. `packages/pocket_sdk/lib/src/pocket_session.dart` fixes cache fallback and generation and timer cancellation. Both are post-audit fixes with service and update lifecycle test records. See [VALIDATION.md](VALIDATION.md) for device verification that remains pending.

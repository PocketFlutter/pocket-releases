# Editor Local Version Server and Test Package Hot Updates

Editor test publishing uses the existing `packageArtifacts`, Ed25519 signatures, and `PocketUpdateCoordinator`, including replay protection via build numbers.

1. In the Editor, select a device and click Run. The trusted server injects the Editor update URL, Ed25519 public key, and isolated `editor_<projectId>` storage namespace into the deployment command. Private keys stay on the server.
2. Edit the JS, save, build, and publish a test package. Send `POST /api/projects/:id/publish` with JSON `{ "channel": "test" }`.
3. In simulator Showcase, open Host → Updates, click Check, then Apply. The host verifies signature, ABI, hash, and build before reloading actual QJBC. This requires no Flutter rebuild.
4. Repeat editing, building, publishing, and Check/Apply. The existing publish interface retains its version semantics for `{}` and `{ "channel": "release" }`.

A test build exceeds the current build configuration, bytecode metadata, published payload, and test publication counter. The version is `<configured version>-test.<build>`. The independent test counter persists when a source save clears publication state and when a normal release is published. Test publishing preserves the release identity in consumer pocket.json and editor.json.

iOS simulators and local desktops can use loopback. Publishing or deploying to a physical device starts a read-only version server on the selected LAN IPv4 address. By default it reuses the Editor port on a different IP. It serves signed release files under `/pocket/<hostVersion>/<packageId>/<packageVersion>/`. Editing, Codex, and deployment APIs are unavailable at this endpoint. Test publishing uses the `test` slot, and releases use `stable`. The signed payload determines the actual version and build. Phone and computer must reach each other on the LAN. Run passes the update URL, public key, storage namespace, and exact debug HTTP host into the app. Private keys stay on the server. The HTTP exception applies only to debug builds. Release builds require secure transport.

On systems with multiple interfaces, `--update-host` or `POCKET_EDITOR_UPDATE_HOST` selects the local LAN IPv4 address, `--update-port` or `POCKET_EDITOR_UPDATE_PORT` sets the read-only port, and `--update-host-version` or `POCKET_EDITOR_HOST_VERSION` sets the host-version path segment. If Publish cannot find a LAN address, it falls back to loopback for simulator testing. Physical deployments give an explicit error. Existing installations lack these build parameters, so use Run once with the updated Editor. Subsequent updates follow Build → Publish test package → App Check → Apply.

The legacy `pocketjs_flutter_demo/pocket_host/editor` signed publication and host.json pipeline had already moved to `sdk/editor/server.ts`. This work reused the retained build and signing flow and the validation scenarios from `demo/integration_test/editor_update_check_test.dart` and `update_lifecycle_test.dart`. It added deployment public-key configuration, monotonically increasing test build numbers, and the test publication endpoint using the existing downloader and verifier.

`sdk/editor/test/editor_server.test.ts` uses the client's public key to verify consecutive test packages, increasing build numbers, and unchanged original configuration. `devices.test.ts` checks actual argv for the public key and update URL. `demo/integration_test/editor_test_package_update_test.dart` uses real JS Check/Apply to verify the native guest changes and the published version remains active after restart. Test and interactive storage use separate namespaces.

Acceptance on an iPhone 18 Pro / iOS 27.2 simulator used temporary Editor port 8793 to publish `0.1.0-test.2` (build 2). The public host.json supplied the integration test's build parameters. Actual UI Check → Apply changed the native guest key, activated the matching version, and kept it active after restart. The result was `1 passed` in about 1m24s. Cleanup affected only the test's `editor_smoke_*` namespace.

`updateConfig` returned undefined for physical devices, leaving `POCKET_UPDATE_*` out of deployment argv. The fix adds the read-only download address and build configuration for physical devices. It reuses signed packages, the Dart coordinator, and relative blob and bundle URLs. The retained parent outside pocket_host provides only in-memory C Syslib AOT switching. See `native/pocket_runtime_multi.c:1215–1343` and `lib/core/pocketjs_bundle_runner.dart:1781–1832` for the legacy implementation.
